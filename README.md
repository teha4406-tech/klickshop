# KlikShop — منصة كتالوجات المتاجر (Firebase مجاني + GitHub Pages)

منصة متعددة المتاجر: **مدير عام** (إنت) بيتحكم في كل حاجة، و**أصحاب محلات** كل واحد ليه لوحة لمتجره بس، و**كتالوج عام** لكل متجر بيستقبل الطلبات على واتساب.

## 1) الملفات ووظيفة كل ملف
| الملف | وظيفته |
|---|---|
| `index.html` + `landing.css` + `landing.js` | الصفحة التسويقية: الخدمات والباقات والتواصل |
| `login.html` + `login.js` | تسجيل الدخول وتحويل المستخدم للوحة دوره |
| `admin.html` + `admin.js` + `admin-extra.js` | لوحة المدير العام: متاجر، أصحاب محلات، باقات واشتراكات، منتجات، طلبات، تقارير، إعدادات المنصة |
| `dashboard.html` + `dashboard.js` | لوحة صاحب المحل: منتجات بصور، تصنيفات، طلبات، بيانات المتجر، الاشتراك |
| `store.html` + `store.js` + `store.css` | الكتالوج العام: `store.html?s=اسم-المتجر` (بحث، تصنيفات، سلة، إرسال الطلب لواتساب) |
| `security-test.html` + `security-test.js` | اختبار قواعد الأمان من الموبايل (كمدير، كصاحب محل، كزائر) |
| `firestore.rules` | **قواعد الأمان الكاملة** (بتتلصق في Firebase) |
| `firebase-config.js` | إعدادات مشروعك `klick-shop` |
| `app.js` / `ui.js` / `images.js` | دوال مشتركة: الأدوار والحماية، النوافذ، ضغط الصور |
| `style.css` / `store.css` / `landing.css` | التنسيقات (عربي RTL) |
| `manifest.json` + `service-worker.js` + `pwa.js` + `icon-*.png` | تثبيت المنصة على الموبايل |
| `404.html` | صفحة "مش موجودة" |
| `package.json` + `firebase.json` + `tests/` | اختبارات Emulator (اختيارية، تحتاج كمبيوتر، **مش لازم تترفع**) |

## 2) الإعداد من الصفر (مرة واحدة)
1. **Firebase (مشروع `klick-shop`، خطة Spark المجانية):**
   - **Authentication ← Sign-in method ← Email/Password** فعّله.
   - **Firestore Database** (Production mode).
   - **Firestore ← Rules**: الصق محتوى `firestore.rules` ← **Publish**.
   - **Authentication ← Settings ← Authorized domains**: ضيف `teha4406-tech.github.io`.
2. **GitHub:** repository اسمه `klikshop` (Public) ← ارفع كل الملفات (من غير `tests/` و`package.json` و`firebase.json`) بأسمائها من غير أرقام ← **Settings ← Pages ← main / (root)**.
   الرابط: `https://teha4406-tech.github.io/klikshop/`
3. **حسابك كمدير عام:**
   - **Authentication ← Users ← Add user** (إيميلك وباسورد قوي) وانسخ الـ **UID**.
   - **Firestore ← Data ← Start collection**: `platformAdmins` ← Document ID = الـ UID ← حقل `email` (string).
4. **فهرس الطلبات (مرة واحدة):** أول ما تفتح تبويب الطلبات هتظهر رسالة فيها رابط، اضغطه واضغط **Create** وانتظر دقايق.

## 3) الاستخدام
**كمدير عام** (`login.html`):
1. **⚙️ الإعدادات:** اسم المنصة وواتساب وإيميل التواصل (بيظهروا في الصفحة التسويقية).
2. **👤 أصحاب المحلات ← ➕:** أنشئ حساب (إيميل وباسورد 6 حروف على الأقل).
3. **🏪 المتاجر ← ➕:** أنشئ متجر برابط إنجليزي صغير (مثال `my-shop`) وواتساب بالكود الدولي (مثال `201012345678`) واربطه بصاحب المحل.
4. **💳 الباقات:** أنشئ الباقات، وبعدها اربط كل متجر باشتراك (باقة وتاريخ انتهاء) وجدّده بزر 🔁.
5. تابع **📦 المنتجات** و**🧾 الطلبات** و**📈 التقارير**. وتقدر توقف أي متجر أو حساب فورًا.

**كصاحب محل:** التصنيفات ← المنتجات (بصور من الموبايل) ← بيانات المتجر ← انسخ رابط الكتالوج وابعته لعملائك. الطلبات بتوصل في تبويب **🧾 الطلبات** وعلى واتساب.

**كعميل:** يفتح رابط الكتالوج ← يختار منتجات ← يبعت الطلب لواتساب المتجر.

## 4) الأمان
- دور المدير العام من وثيقة `platformAdmins/{uid}` بتتعمل يدويًا من Console، والقواعد بتمنع أي كتابة عليها من الموقع.
- محدش يقدر يغيّر دوره أو يرقّي نفسه (كل كتابة في `users` للمدير العام بس).
- عزل المتاجر: كل منتج وتصنيف وطلب ليه `storeId`، والقواعد بتتأكد إن صاحب المحل بيملك المتجر وإن حسابه ومتجره شغّالين.
- الزائر يقرا الكتالوج الظاهر بس، ويبعت طلب بشروط صارمة (حالة `new`، ووقت السيرفر، ومتجر شغّال).
- مفيش أسرار في الكود (إعدادات Firebase للويب مش أسرار، والحماية في القواعد).

## 5) الاختبارات
1. **من الموبايل:** افتح `security-test.html`: شغّله كمدير عام، وكصاحب محل (لازم متجرين شغّالين)، وكزائر (زر **اختبار كزائر**). المفروض كله ✅.
2. **على كمبيوتر (اختياري):** `npm install` ثم `npm test` (15 حالة على Firebase Emulator). ⚠️ ما اتشغّلتش من عندي، جرّبه قبل ما تعتمد عليه.

## 6) حدود النسخة المجانية
- مفيش Storage: الصور بتتضغط وتتخزن في Firestore (حتى 5 صور للمنتج).
- مفيش Cloud Functions: كل حاجة بتتنفذ من المتصفح، والأمان في القواعد.
- حد حوالي 50 ألف قراءة/يوم. الكتالوج بيحتفظ بالبيانات 3 دقايق على موبايل الزبون لتوفير القراءات.
- حد منتجات الباقة بيتطبّق في الواجهة بس (مش في القواعد).
- حذف حساب صاحب محل بيمنعه من الدخول، لكن إيميله بيفضل في Authentication لحد ما تمسحه يدويًا.
- معاينة رابط الكتالوج في واتساب بتبقى عامة (مش باسم المتجر) لأن الصفحة ثابتة.
